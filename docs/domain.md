# 领域说明

投研结论由公司指标、预测期间、情景、公式版本和外部数据共同构成。同一份观点可能由多人在
不同分支修改：数据源修订会使部分假设过期（`stale`）并沿计算血缘传播到下游结论，但不会
改变已经生成的提交快照或已发布版本；分析师重新确认取值（在新提交中写入新值并绑定数据源
新修订）才会清除过期标记。引用材料、审批意见和计算依赖是解释估值差异的依据。

核心不变量（由服务端保证，测试覆盖）：

- **稳定标识**：公司、指标（项目内 `key`）、数据源、提交、公式版本、评审、发布均有稳定 ID。
- **三种时间**：业务发生时间 `business_date`、系统接收时间 `set_at`/`created_at`、
  以及严格递增的版本序号 `seq`，分开保存。
- **快照不可变**：提交保存全部输入值、所用公式版本 ID、常量与内容 `digest`；
  公式新版本不会回改旧提交，旧提交在状态接口中显示 `outdated_formulas`。
- **依赖防环**：公式只允许白名单 AST，同期间度量依赖在写入依赖图前做环检测；
  `prev/at/scenario` 属于跨上下文引用，不参与同图环判定。
- **合并粒度**：乐观并发（`expected_parent`）冲突报告精确到 `指标 × 期间 × 情景`，
  常量冲突单独列出。
- **评审追加**：评论只增不改；状态机为
  `submitted → approved / changes_requested → submitted(reopen)`。
- **发布唯一**：每个项目至多一个权威 Release；线程锁 + 文件锁保证跨进程并发下只有一个赢家，
  导出包含数据摘要 digest、公式版本清单与审批人，事后数据源再修订不影响导出内容。
- **权限隔离**：`watchlist` 项目仅对成员中同时具备 `watchlist_access` 的用户可见可操作。

`reference/domain.json` 保存可公开的示例枚举与精度约定。
