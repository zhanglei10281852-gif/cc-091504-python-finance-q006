# 领域说明

投研结论通常由公司指标、预测期间、情景、公式和外部数据共同构成。同一份观点可能由多人在不同分支修改，数据源修订会使部分假设过期，但不应改变已经发布的版本。引用材料、审批意见和计算依赖是解释估值差异的重要依据。

`reference/domain.json` 保存可公开的示例枚举与精度约定。正式业务记录应使用稳定标识，并区分业务发生时间（`business_time`）、系统接收时间（`received_time`）和记录版本（`revision`）。

## 已实现的核心模型

- **项目**：`normal`（全员可读）与 `watchlist`（敏感观察名单，仅成员可见，对非成员按不存在处理）。成员角色：`lead` / `analyst`（写）、`reviewer` / `lead`（审批发布）。
- **假设**：以 指标 × 期间 × 情景 为单元格，挂在分支上，可挂数据来源与引用材料；`status` 为 `current` / `stale`。
- **外部数据**：同（来源, 指标, 期间）的新 `observation` 视为修订，旧记录被取代；修订只把相关假设标记为 `stale`，不改写任何已发布版本快照。
- **公式**：表达式按同公司指标代码引用依赖，写入前判环（直接环与间接环均拒绝），每次更新版本号递增；合并后整体公式图再次判环。
- **分支与合并**：分支从最新已发布基线物化而来；三方合并进 `main`，冲突精确到 指标 × 期间 × 情景（公式到指标），冲突时整体不落地。
- **发布**：`expected_version_id` 在锁内 compare-and-swap，并发发布最多产生一个权威版本；基线过期返回 `409 stale_base`。
- **复核意见**：只追加，无修改与删除入口。
- **导出**：固定版本的数据摘要（`data_digest`）、各指标公式版本与审批人，内容不可变。
- **追溯与差异**：`compute` 返回从估值结论到输入来源（含来源修订号、引用材料）的完整计算路径并传播 `stale`；`pending` 列出待重算结论；`diff` 把版本间结论差异归因到 `data`（输入假设变化）或 `model`（公式变化）。
